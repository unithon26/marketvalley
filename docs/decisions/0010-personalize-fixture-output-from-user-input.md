# ADR-0010: mock 생성기도 입력값을 산출물 슬롯에 보존한다

상태: 채택

기준일: 2026-08-25

## 배경

기존 `FixtureCampaignGenerator`는 배경과 솔루션에서 키워드로 reference fixture 하나를 고른 뒤 완성된 `CampaignSpec`을 그대로 복사했다. API·저장·공개·ZIP 경계는 실제로 동작했지만, 사용자가 쓴 상품명과 특징이 랜딩페이지와 카드뉴스에 반영되지 않았다. Figma의 랜딩 도입부는 상품명, 한 줄 특징, 핵심 특징 키워드와 상품 설명을 넣는 고정 슬롯을 전제로 하므로 템플릿 ID만 선택하는 것으로는 산출물이 완성되지 않는다.

## 결정

- `/new`의 Figma 2단계 입력인 배경과 솔루션은 유지한다. 솔루션 안내에서 제품·서비스 이름과 핵심 특징을 함께 적도록 돕는다.
- mock 생성기는 reference fixture를 색상과 Figma 템플릿 선택에만 사용한다. 고객·업종 문구는 중립 골격으로 교체하고, 입력에서 명시된 상품명과 특징 3개를 결정적으로 추출해 문제와 솔루션 원문과 함께 계약 길이에 맞춰 `CampaignSpec`에 보존한다.
- `project.name`은 상품명, `project.oneLiner`는 입력 솔루션의 한 줄 설명, `landing.benefits`의 제목 3개는 Figma 특징 키워드의 단일 source field로 사용한다.
- 랜딩 도입부 `1`~`7`, 공통 하단 섹션, 캐러셀 5장, 캡션·해시태그와 `Meta 게시 준비` 파일은 위 필드를 직접 참조한다.
- 이름이 없으면 `새 시장검증 캠페인`, 특징이 부족하면 업종과 무관한 안전한 기본 특징으로 보완한다. 키워드 하나가 겹쳐도 reference의 고객·단계·FAQ·해시태그가 산출물에 섞이지 않는다. 이 동작은 발표용 결정적 fallback이며 AI 추론으로 표현하지 않는다.
- 카드뉴스 2~5장은 Figma에 별도 후속 장이 없으므로 임의의 다른 테마를 사용하지 않고 선택된 표지 `31`·`32`·`34`의 타이포, 사진, 흑백·보라 강조 규칙을 이어받는다.

## 기각한 대안

### fixture 완성본을 그대로 반환한다

재현성은 높지만 사용자 입력이 산출물에 나타나지 않아 제품의 핵심 경로를 증명하지 못한다.

### 상품명과 특징을 별도 3단계 폼으로 추가한다

구조화 입력은 쉬워지지만 확정된 Figma 2단계 흐름과 맞지 않고 사용자가 해야 할 입력 작업을 늘린다. mock에서는 솔루션 문장에 명시된 정보를 결정적으로 추출하고, live 단계에서는 OpenAI Structured Outputs가 같은 `CampaignSpec`을 채운다.

### mock 단계에서도 외부 모델을 호출한다

임의 입력 대응은 좋아지지만 네트워크·키·모델 출력 실패가 발표를 막을 수 있어 기각했다. 외부 adapter는 같은 계약을 구현하는 후속 단계로 유지한다.

## 결과

같은 입력에서 상품명과 특징이 공개 랜딩, 캐러셀 PNG, 게시 문구와 Meta 준비 파일까지 일관되게 이어진다. mock은 여전히 실제 시장 사실이나 효과를 생성하지 않으며, reference 밖 입력의 문장 품질 한계는 OpenAI adapter 교체 전까지 남는다.
