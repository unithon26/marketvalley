# ADR-0005: 시각 참고 요소와 디자인 확정 전 화면 구현을 보류한다

상태: 채택
날짜: 2026-08-24

## 배경

팀의 랜딩페이지 시각 참고용 코드는 이미 GitHub에 있고 메인 웹사이트는 디자인 담당자가 제작 중이다. 별도 임시 화면을 먼저 만들면 디자인 반영 과정에서 중복 작업과 불필요한 시각 기준이 생긴다.

## 결정

- 현재 저장소의 이전 임시 제품 화면과 관련 API, mock 구현, fixture와 화면 테스트를 제거한다.
- 문서와 Next.js·TypeScript·Tailwind 중심 개발환경만 유지한다.
- 랜딩페이지 저장소는 시각 요소만 참고하고 구조와 기능은 제품 스펙을 따른다.
- 메인 웹사이트는 디자인 담당자의 확정본을 받은 뒤 구현한다.
- 이전 임시 화면은 코드나 시각 참고자료로 보존하지 않는다.
- 발표는 사람이 직접 조작하며 자동 재생이나 자동 클릭 기능을 넣지 않는다.

## 기각한 대안

### 임시 화면을 참고용으로 보존

빠르게 재사용할 수 있지만 확정 디자인과 다른 구조가 암묵적인 기준이 되고 잘못된 코드를 다시 가져올 가능성이 있다.

### 임시 화면을 먼저 완성한 뒤 디자인을 덮어쓰기

종단 흐름을 빨리 확인할 수 있지만 레이아웃과 컴포넌트 구조를 두 번 구현하게 되어 3일 일정에서 비용이 크다.

## 결과

- 현재 저장소는 실행 가능한 제품이 아니라 기획 문서와 개발 준비 상태만 제공한다.
- UI 구현 시작 조건과 시각적 권위가 명확해진다.
- 디자인 전달 전에는 계약, 데이터 경계, 운영 규정과 발표 논리를 정리할 수 있다.
