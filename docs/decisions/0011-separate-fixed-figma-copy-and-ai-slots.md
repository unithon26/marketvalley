# ADR-0011: Figma 고정 영역과 AI 문구 슬롯을 분리한다

상태: 채택

기준일: 2026-08-25

## 배경

Figma에는 랜딩 도입부 7종과 카드뉴스 표지 3종의 배치·타이포·색상 규칙이 있고, `CampaignSpec`에는 사용자의 아이디어에 따라 달라져야 할 고객·문제·가치제안·후킹·랜딩·캐러셀 문구가 있다. 이 둘을 구분하지 않으면 모델이 디자인과 안전 안내까지 임의로 바꾸거나, 결과물별 독립 호출에서 고객·문제·CTA가 서로 달라질 수 있다.

## 결정

- Figma가 정의한 레이아웃, 섹션 순서, 타이포·색상 조합, 진행·리포트 UI와 개인정보·판단 안내는 React/CSS renderer에 고정한다.
- AI는 HTML, 좌표, 새 템플릿이나 상태 문구를 만들지 않는다. 허용된 `carouselCover`, `landingIntro`, `tone`만 선택하고 실제 색상과 시각 방향은 서버가 Figma 토큰으로 매핑한다.
- 상품 요약, 검증 가설, 선택형 관심 질문, 가치제안, 후킹 3종, 게시 문구, 랜딩 각 섹션, 캐러셀 각 장과 선택적 텍스트 없는 배경 설명에는 각각 목적·길이·금지사항이 다른 프롬프트 지시를 둔다.
- 후킹 문구는 고객의 반복 순간, 사라지는 일과 작동 방식, 사람이 되찾는 판단과 다음 행동이라는 서로 다른 세 각도로 만든다. 확인되지 않은 수치·공포·성과 보장은 사용하지 않는다.
- 슬롯별 지시는 하나의 developer prompt로 조합하고 Responses API Structured Outputs 한 번으로 전체 `CampaignSpec`을 생성한다. 결과물별로 모델을 따로 호출하지 않는다.
- 사용자 입력은 별도 user message의 JSON 자료로 전달하고 그 안의 지시문을 실행하지 않는다. 사용자 입력, prompt version과 모델 결과를 구분해 추적한다.
- 스키마 버전, 모델·생성 시각, Figma 색상, 판단 기준 `응답 5개 중 긍정 3개`, 캠페인 ID·slug·공개 URL과 실제 응답은 서버가 소유한다. 모델 출력은 Zod 재검증 뒤 이 값들로 덮어쓴다.
- 입력에 없는 후기, 고객 수, 가격, 매출·효능·인증·수상과 시장 검증 완료 주장을 만들지 않는다. 추론은 `validation.assumptions`, 확인할 주장은 `safety.claimsToReview`에 분리한다.

프롬프트 계약의 기준 파일은 `lib/ai/campaignPrompts.ts`다. live adapter가 추가돼도 renderer의 텍스트 슬롯과 디자인 경계는 바꾸지 않는다.

## 기각한 대안

### 랜딩·캐러셀·Meta 문구를 각각 별도 호출한다

각 채널에 최적화하기 쉽지만 고객, 문제, 특징과 CTA가 어긋날 수 있고 사용자가 다시 정합성을 확인해야 하므로 기각했다.

### 모든 문구를 하나의 포괄적인 지시로 생성한다

호출은 단순하지만 후킹, FAQ, CTA와 카드 본문이 같은 기준으로 작성되어 목적과 길이에 맞는 품질을 안정적으로 얻기 어렵다.

### 모델이 전체 랜딩 HTML과 카드 이미지를 만든다

Figma 정합성, 정확한 한글 조판, 접근성, PNG 회귀와 안전 문구 고정이 어려워 기각했다.

## 결과

디자인은 결정적으로 유지하면서 사용자 입력에 따라 바뀌어야 할 모든 문구에 명시적인 생성 기준이 생긴다. 한 번의 생성 결과를 랜딩, 카드뉴스, 게시 준비 파일이 공유하므로 채널별 재작성과 정합성 확인을 다시 만들지 않는다. 실제 문구 품질은 OpenAI adapter를 연결한 뒤 대표 입력과 경계 입력 eval로 추가 검증해야 한다.
