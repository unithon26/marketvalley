# ADR-0007: 발표 흐름을 결정적 mock으로 완성한다

상태: 채택
날짜: 2026-08-24

## 배경

메인 웹사이트 Figma 디자인이 전달됐고 발표에서 전체 제품 흐름을 우선 시연해야 한다. OpenAI, Supabase와 Meta 계정을 동시에 연결하면 외부 장애와 권한 문제가 핵심 데모를 막을 수 있다.

## 결정

- Figma의 홈, 2단계 입력, 진행 상태와 리포트 구조를 제품 화면에 반영한다.
- 검증된 `CampaignSpec` fixture 하나로 랜딩, 캐러셀, 게시 문구와 익명 관심 신호를 모두 렌더링한다.
- 응답과 사람의 다음 판단은 발표 브라우저의 `localStorage`에 저장한다.
- 캐러셀은 같은 React/CSS 렌더러에서 1080×1350 PNG 5장과 ZIP으로 만든다.
- Meta는 게시 준비 파일과 복사 기능만 제공하고 실제 계정 연결·게시·지출을 하지 않는다.
- Figma의 예약·이메일 지표는 개인정보 없는 선택형 관심 신호와 사전 판단 기준으로 치환한다.
- 모든 목 수치와 외부 미연동 상태를 화면에 명시한다.

## 기각한 대안

### 외부 adapter를 먼저 연결한다

실제 다중 기기 공유에는 유리하지만 짧은 발표 준비 기간에 인증, 네트워크와 데이터 상태가 실패 지점을 늘린다.

### Figma의 예약·이메일 수집을 그대로 구현한다

디자인과 가장 유사하지만 P0의 개인정보 비수집 원칙과 실제 제품 지표에 어긋난다.

## 결과

- 외부 키와 네트워크 없이 핵심 발표 흐름을 반복 재현할 수 있다.
- 현재 응답은 브라우저 안에서만 유지되며 실제 조사나 공개 서비스 데이터로 해석할 수 없다.
- live 전환은 기존 `CampaignSpec`과 화면을 유지한 채 생성·저장 adapter를 교체하는 후속 작업이다.
