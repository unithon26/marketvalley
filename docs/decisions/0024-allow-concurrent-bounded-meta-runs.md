# ADR-0024: 예산이 제한된 Meta 광고를 캠페인별로 동시 집행한다

상태: 채택
날짜: 2026-08-26

## 맥락

ADR-0023은 공유 광고계정의 중복 지출을 막기 위해 계정당 live run을 하나로 제한했다. 실제 운영에서 첫 광고가 24시간 수집되는 동안 뒤에 접수한 광고 두 건은 랜딩·카드뉴스와 Meta `PAUSED` 객체까지 완성하고도 `AWAITING_ACTIVATION`에 머물렀다. 화면에는 대기 이유가 없었고, 초안 생성 시점에 고정된 수집 종료 시각 때문에 대기가 길수록 뒤 광고의 실제 수집 구간도 짧아질 수 있었다.

## 결정

계정 전체를 직렬화하는 partial unique index와 worker의 다른 live run 조회를 제거한다. 각 광고는 기존과 같이 허용된 운영자 UUID, 정확한 광고계정, 고정 lifetime 예산, 시작·종료 시각을 활성화 직전에 검증한다. Meta 객체는 `PAUSED`로 만든 뒤 자식부터 부모 순서로 활성화하고, 일부 실패 시 전체를 다시 `PAUSED`로 복구한다.

동시에 집행되는 광고마다 독립된 `meta_ad_runs`와 Insights snapshot을 사용한다. 자동 예산 증액, 종료 광고 재시작과 결제수단 등록은 계속 허용하지 않는다.

## 기각한 대안

- 계정당 하나를 유지하고 대기열만 표시: 뒤 광고의 검증이 하루씩 밀리고 수집 일정 재조정용 외부 상태 변경이 추가된다.
- 대기 중 ad set 일정을 반복 수정: Meta와 DB 두 곳의 시간 동기화와 조정 실패 복구가 필요하다.
- 계정 전체 무제한 예산: 동시 실행과 무제한 지출은 별개이며, 캠페인별 고정 lifetime 예산을 유지해야 한다.

## 결과

사용자는 여러 아이디어를 연속 접수해도 각 광고가 준비 완료 뒤 독립적으로 실제 수집 단계로 넘어간다. 총지출은 동시 캠페인 수만큼 늘 수 있지만 각 캠페인의 최대 지출은 서버 승인값을 넘지 않는다. 운영자는 캠페인별 상태와 Insights를 독립적으로 추적한다.
