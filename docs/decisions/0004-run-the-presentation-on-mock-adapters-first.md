# ADR-0004: 발표 흐름을 mock adapter로 먼저 완성한다

상태: ADR-0005로 대체
날짜: 2026-08-24

## 배경

OpenAI, Supabase와 Meta를 동시에 연결하면 계정·권한·네트워크 실패가 화면과 상태 설계의 문제와 섞인다. 발표용 핵심은 외부 서비스 수가 아니라 반복 제작·취합 단계가 실제 하나의 흐름에서 사라지는 모습을 끝까지 보여주는 것이다.

## 결정

- 첫 완료 단위는 외부 자격증명이 전혀 필요 없는 mock-first P0다.
- mock과 live는 같은 `CampaignSpec`, 렌더러와 repository 인터페이스를 사용한다.
- mock 생성은 완성된 fixture를 입력값에 맞춰 안전하게 복제한다.
- mock 공개·응답·판단은 브라우저 저장소에 유지하고 데이터가 다른 기기와 공유되지 않는다는 한계를 표시한다.
- seed 응답은 실제 사용자 데이터처럼 보이지 않도록 `데모 데이터`로 명시한다.
- 발표는 사람이 직접 클릭한다. 자동 재생이나 자동 클릭을 제품 기능으로 넣지 않는다.
- E2E 자동화는 개발 단계의 회귀 테스트에만 사용한다.
- mock P0가 전체 검증 게이트를 통과한 뒤 Supabase, OpenAI 순서로 adapter를 교체한다.

## 기각한 대안

### 외부 연동부터 구현

실데이터를 일찍 볼 수 있지만 계정 준비와 장애가 전체 발표 경로를 막고 두 개발자의 병렬 작업 경계를 흐린다.

### 발표 자체를 자동 클릭으로 재생

동일한 장면은 재현하기 쉽지만 실제 제품 조작과 상태 변화를 증명하기 어렵다. 자동화는 테스트에만 남긴다.

### mock 전용 별도 화면

빠르게 꾸밀 수 있지만 live 전환 때 화면과 상태를 다시 만들어야 하고 발표가 실제 구현을 대표하지 못한다.

## 결과

- 이 순서로 임시 mock 화면을 만들었으나 디자인 기준이 되지 않도록 제품 코드를 제거했다.
- mock-first 원칙은 유지하지만 기존 랜딩페이지 템플릿과 메인 웹사이트 디자인을 먼저 확인한 뒤 다시 구현한다.
- 발표 자동 재생은 만들지 않는다는 결정은 유지한다.
