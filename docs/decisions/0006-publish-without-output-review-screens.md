# ADR-0006: 산출물 사전 확인 화면을 두지 않는다

상태: 부분 대체됨 — 별도 가설 승인 화면은 ADR-0008에서 제거
날짜: 2026-08-24

## 배경

이전 스펙은 가설, 랜딩, 캐러셀과 판단을 오가는 별도 편집 화면을 두었다. 이 구조는 사용자가 결과물을 다시 확인하고 수정하는 일을 추가해, 캠페인 제작 업무를 없앤다는 제품 약속과 맞지 않는다.

## 결정

- 사용자는 아이디어 입력 뒤 고객, 문제, 해결, 기대 신호, 반증 조건, 사전 판단 기준과 사실 검토 항목만 승인한다.
- 승인하면 공개 랜딩 URL, 캐러셀 PNG·ZIP과 게시 문구 패키지를 바로 생성한다.
- 랜딩, 캐러셀과 Meta용 산출물을 제품 화면 안에 다시 그리지 않는다.
- 실제 랜딩은 공개 URL에서 확인하고 캐러셀은 내려받은 파일을 최종 결과로 사용한다.
- 승인된 `CampaignSpec` snapshot은 수정하지 않는다. 변경이 필요하면 기존 입력을 불러와 새 캠페인을 생성한다.
- `/campaigns/[id]`는 실제 URL·파일·문구 전달과 응답 분포·사람의 다음 판단만 담당한다.

## 기각한 대안

### 탭형 캠페인 편집 화면 유지

세밀한 수정은 가능하지만 사용자가 채널별 결과를 다시 확인하고 조정해야 하므로 제거하려던 업무가 제품 안에 남는다.

### 생성 뒤 자동 공개

단계는 가장 적지만 사실 표현과 검증 가설을 사람이 확인할 기회를 없앤다. 가설 승인은 안전성과 책임을 위해 유지한다.

## 결과

- P0 핵심 경로는 `아이디어 입력 → 가설 승인 → 게시·파일 생성 → 실제 응답 → 사람의 판단`으로 단순해진다.
- 디자인 담당자는 입력, 가설 승인, 캠페인 결과와 공개 랜딩 상태만 설계하면 된다.
- 사용자는 채널별 조판과 정합성 확인을 다시 수행하지 않는다.
- 메시지 변경은 기존 공개 캠페인을 덮어쓰지 않고 새 실험으로 남는다.
