# ADR-0013: 익명 선택형 신호를 이름·이메일 예약자명단으로 전환한다

상태: 채택

기준일: 2026-08-25

## 배경

ADR-0001은 제품의 완료점을 "산출물 생성"이 아니라 "개인정보 없는 선택형 관심 신호 + 사람의 다음 판단"으로 정했고, `docs/validation.md`는 이름·이메일·전화번호를 받지 않는다고 명시했다. 오늘 개발자 B는 이 원칙에 따라 이름·이메일 수집과 고정 광고 지표 표시를 제안한 다른 브랜치를 반려했다 (`WORKLOG.md` 2026-08-25 "개발자 A/B 충돌 PR 정리" 항목).

같은 날, 제품 책임자(개발자 A)는 레퍼런스 랜딩(`proo-landing.vercel.app`)의 "DELIVERABLE — 이런 리포트를 받습니다" 구성(노출수·CTR·예약률·랜딩 체류시간·이탈률과 이름·이메일 예약자명단)을 실제 제품 방향으로 채택하기로 의도적으로 결정했다. 이 ADR은 그 결정과 근거를 기록하고, 이전에 반려됐던 방향이 이번엔 승인된 의사결정이라는 점을 developer B/Codex 세션에 알리기 위해 작성한다.

## 결정

- `CampaignSpec.validation.signal`의 긍정·중립·부정 3지선다 익명 응답을 폐기하고, 이름·이메일과 개인정보 동의 체크박스를 받는 예약자명단 폼으로 대체한다.
- 계정 개념은 아직 도입하지 않는다. 지금처럼 단일 데모 공간(캠페인별 예약자명단)만 유지하고, 캠페인 소유권(로그인 계정별 격리)은 실제 OAuth 연결 시점에 별도로 설계한다.
- 결제·입금 연동은 이번 스코프에서 완전히 제외한다. 레퍼런스의 "실입금 사전예약" 지표는 구현하지 않는다.
- 리포트에는 실제 데이터와 예시(목업) 데이터를 명확히 구분해 표시한다.
  - 실제 데이터: 예약자 수, 예약자 리스트(마스킹된 이메일).
  - 예시 데이터: 노출 수, CTR, 랜딩 체류시간, 이탈률, 예약률(업계 평균 비교 포함). 실제 트래킹을 구현하지 않으므로 화면에 "예시 지표" 또는 이에 준하는 라벨을 반드시 표시해, 실측치로 오인되지 않게 한다.
- 중복 제출 방지 키를 `visitorId` 기준에서 `(campaignId, email)` 기준으로 바꾼다. 기존에 스캐폴딩된 `SIGNAL_HASH_SECRET`을 이메일 해시/dedupe에 재사용한다.
- 공개 랜딩과 프롬프트 파일(`lib/ai/campaignPrompts.ts`)의 "개인정보를 받지 않는다"류 신뢰 문구는 전부 "동의 후 예약자명단에 포함됩니다"류로 교체한다.
- UTM 파라미터(`utm_source`/`utm_medium`/`utm_campaign`/`utm_content`)를 랜딩 진입 시 읽어 예약 기록에 함께 저장한다. 이번 스코프에서는 저장까지만 하고, 소재 변형별(A/B) 집계·분석 UI는 만들지 않는다.

## 이번 결정이 ADR-0001과 다른 점

ADR-0001의 "산출물 생성이 아니라 검증 루프를 닫는다"는 구조(아이디어 → 가설 → 랜딩/캐러셀 → 공개 → 관심 신호 수집 → 사람의 판단)는 그대로 유지한다. 바뀌는 것은 "관심 신호를 어떻게 기록하는가" 한 가지뿐이다 — 익명 선택형 응답에서 이름·이메일 기반 예약자명단으로. "시장 검증이나 사업 성공을 보장한다는 표현을 사용하지 않는다"는 ADR-0001의 원칙과, 예시 지표에 반드시 라벨을 붙인다는 이번 결정의 조건은 계속 유효하다.

## 기각한 대안

### 기존 3지선다 신호는 유지하고 이메일만 별도 옵트인으로 추가

개인정보 미수집 원칙과 충돌하지 않고 기존 e2e 테스트 대부분을 보존할 수 있어 가장 안전한 선택지였다. 그러나 제품 책임자가 레퍼런스 리포트 형태(예약자명단 중심)를 데모 목표로 명시적으로 선택하면서 기각했다.

### 노출수·CTR 등도 전부 실측으로 구현

"측정값 진실성" 원칙을 그대로 지킬 수 있지만, 페이지뷰·클릭·체류시간 트래킹 인프라를 2일 해커톤 범위에서 새로 구현해야 해서 기각했다. 대신 예시 데이터임을 라벨로 명시하는 절충안을 택했다.

## 결과

- `docs/spec.md`의 P0-4, 지표 정의, Supabase 스키마 스케치와 `docs/validation.md`의 "안전성과 진실성" 절이 이 ADR을 반영해 갱신된다.
- `tests/e2e/demo-flow.spec.ts`의 3지선다·긍정 신호율 관련 검증 대부분이 새 예약자명단 흐름 기준으로 다시 작성돼야 한다.
- 상세 구현 계약과 단계별 작업 분담은 `docs/superpowers/specs/2026-08-25-reservation-list-migration-design.md`에 기록한다.
