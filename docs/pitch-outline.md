# 3분 발표 구성

상태: mock 화면 기준 발표 원고 초안
기준일: 2026-08-24

## 핵심 문장

`marketvalley는 콘텐츠를 더 만드는 도구가 아니라, 예비창업자가 첫 고객 반응을 보기 전 반복하던 제작·정리 업무를 없애는 도구입니다.`

## 슬라이드와 멘트

### 1. 사람과 상황 — 20초

아이디어는 있지만 아직 제품을 만들지 않은 예비창업가를 보여준다.

“아이디어가 없는 것이 아닙니다. 잘될지 확신이 없어 첫 검증을 시작하지 못합니다.”

### 2. 사라져야 할 일 — 25초

고객·문제 재작성, 랜딩 제작, 카드 조판, 게시 문구 재입력과 반응 취합을 동일한 입력의 Before 흐름으로 보여준다.

정확한 단계 수는 최종 리허설에서 직접 세어 `[Before N단계]`로 교체한다.

### 3. 제품 원리 — 20초

하나의 `CampaignSpec`이 검증 가설, 랜딩, 캐러셀, 게시 준비와 응답을 연결하는 그림을 보여준다.

“화면을 여러 개 생성한 것이 아니라, 같은 가설을 여러 도구에 다시 옮기는 일을 없앴습니다.”

### 4. 실제 데모 — 75초

1. 아이디어 예시를 불러와 캠페인을 만든다.
2. 검증 가설과 반증 조건을 확인한다.
3. 가설을 승인해 공개 URL과 캐러셀 ZIP이 한 번에 생성되는 것을 보여준다.
4. 공개 페이지에서 선택형 응답을 제출한다.
5. 결과 화면에서 응답 증가와 표본 부족을 확인한다.
6. 발표자가 다음 행동을 직접 선택하고 ZIP을 내려받는다.

자동 클릭이나 녹화 재생으로 라이브 데모를 대신하지 않는다. 향후 E2E 도구는 개발 검증에만 사용한다.

### 5. 없어진 일의 증거 — 25초

구현 완료 후 같은 발표자가 같은 입력으로 세어 확정한다.

- 제거된 채널별 재작성: `[측정 예정]`
- 제거된 조판·파일 정리: `[측정 예정]`
- 제거된 별도 반응 취합: `[측정 예정]`
- 남은 사람의 판단: 가설 승인, 공개, 계속·수정·보류

측정하기 전에는 시간 절감률을 넣지 않는다.

### 6. 한계와 다음 검증 — 15초

“지금 보신 응답은 데모 데이터이고 시장성이 검증됐다는 뜻이 아닙니다. 다음 단계는 실제 예비창업자의 캠페인을 공개하고, 제작 단계가 실제로 사라졌는지 측정하는 것입니다.”

## 예상 질문

### Canva·Lovable과 무엇이 다른가?

결과물 생성에서 끝나지 않고 검증 가설과 반증 조건을 먼저 고정하고, 공개 응답을 같은 가설에 연결한 뒤 사람의 다음 판단으로 끝난다.

### 응답이 적은데 시장성을 판단할 수 있나?

판단하지 않는다. 응답 수·분포와 사전 기준, 표본 부족을 표시하고 다음 행동은 사람이 선택한다.

### 왜 연락처 예약을 받지 않나?

P0의 목표는 최소 관심 신호를 안전하게 연결하는 것이다. 연락처를 받으면 개인정보 보관·동의 범위가 커지고 해커톤 핵심을 흐린다.

### Meta 광고를 실제로 집행하나?

P0는 게시 준비 패키지만 제공한다. 실제 계정 연결과 지출은 범위 밖이며, 선택적 P1도 팀 테스트 계정의 `PAUSED` 생성까지만 허용한다.

### AI가 꼭 필요한 부분은?

자유 형식 아이디어를 고객·문제·솔루션·기대 신호·반증 조건과 채널별 제한을 만족하는 단일 구조 계약으로 변환하는 부분이다. 조판과 상태 전파는 결정적 코드가 담당한다.

## 백업

- 구현 후 네트워크 없이 같은 renderer로 동작할 fixture
- 발표용 공개 탭과 사전 다운로드한 PNG/ZIP
- 화면 녹화는 라이브 데모 실패 시에만 사용
- OpenAI·DB 각각을 끈 실패 안내 리허설
