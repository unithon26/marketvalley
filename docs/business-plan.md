# marketvalley 사업계획 초안

상태: 검증 전 가설
기준일: 2026-08-25

## 사업 개요

marketvalley는 제품을 만들기 전 첫 시장 반응을 확인하려는 예비창업가의 검증 광고 제작·집행 확인·결과 취합을 없앤다. 아이디어 하나에서 검증 가설, 공개 랜딩, Instagram 캐러셀, Meta 광고와 동의 기반 예약자명단을 같은 데이터 계약으로 연결한다.

시장조사나 사업 성공을 대신 판정하지 않는다. 시스템은 관찰된 신호와 사전에 승인한 기준을 보여주고, 계속 검증·메시지 수정·보류는 사용자가 결정한다.

## 고객과 문제

첫 고객은 아이디어는 있지만 제품을 아직 만들지 않은 예비창업가와 초기 1인 사업자다. 이들은 첫 반응을 확인하기 전에 고객·문제·솔루션을 반복해 쓰고, 랜딩과 카드뉴스를 서로 다른 도구에서 조립하고, 반응을 다시 취합한다.

검증할 핵심 문제는 “확신이 없어 시작하지 못한다”가 아니라 “검증 방법과 준비 작업이 복잡해 실제 고객 행동을 확인하기 전에 멈춘다”이다.

## 제품

P0:

- 검증 가설과 반증 조건
- 단일 spec 기반 랜딩·캐러셀·게시 문구
- 공개 URL과 이름·이메일·동의를 받는 예약 폼
- 예약자 수·접수 추이·표본 부족·사람의 다음 행동
- PNG/ZIP, 제한된 Meta 자동 집행과 Insights 최종 리포트
- 외부 계정과 분리한 결정적 fixture 발표 경로

운영 자동화는 팀 소유 테스트 계정과 캠페인별 고정 lifetime 예산에만 연다. 독립적으로 예산이 제한된 광고는 동시에 집행할 수 있으며, 사용자별 Meta OAuth, 결제수단 등록, 자동 예산 증액과 종료 광고 재시작은 범위에서 제외한다.

## 고객 가치

- 디자인 도구와 웹 빌더를 오가는 조판 업무 제거
- 채널별 카피 재작성과 메시지 정합성 확인 제거
- 공개 반응의 별도 취합 제거
- 결과를 과장하지 않고 사람의 판단 책임 유지

## 수익 모델

1. 개인 사용자: 캠페인 1건 단위 결제 또는 제한된 월 구독
2. 창업지원기관: 프로그램 기수 단위 좌석·캠페인 계약
3. 교육기관: 시장검증 실습용 cohort 라이선스와 운영 대시보드

팀이 제시한 개인 건당 10만~20만 원은 검증 대상 가격 가설이다. 무료 도구 조합 대비 지불 의향, 반복 사용 빈도와 기관 담당자의 구매 절차를 인터뷰해야 한다.

## 시장 진입

1. 교내 해커톤에서 수동 단계 감소와 실제 응답 연결을 증명한다.
2. 최근 아이디어 검증을 시도한 예비창업자 3명을 인터뷰한다.
3. 한 번의 실제 캠페인을 함께 실행하고 제거된 단계·재작업을 측정한다.
4. 창업동아리·지원단의 한 기수에서 운영 가치를 검증한다.
5. 반복 사용과 지불 의향이 확인된 뒤 가격·구독 구조를 실험한다.

## 운영과 기술

- Next.js 단일 애플리케이션과 Oracle Compute 컨테이너 배포
- Anthropic Messages API Structured Outputs 기반 `CampaignSpec`
- Supabase snapshot, 동의 기반 예약자명단과 다음 행동 저장
- React/CSS 결정적 렌더러와 PNG/ZIP export
- fixture/live adapter를 통한 장애 격리와 재현 가능한 데모

## 핵심 위험과 대응

| 위험 | 대응 |
| --- | --- |
| 생성 도구의 축소판으로 보임 | 실제 예약자명단과 사람의 다음 판단까지 닫힌 루프를 P0로 둔다. |
| 작은 표본을 시장성으로 과장 | 예약자 수·표본 부족만 표시하고 자동 판정을 금지한다. |
| 근거 없는 후기·성과 생성 | Zod 안전 필드, 사실 확인 경고와 발표 체크리스트를 사용한다. |
| Meta 권한·지출 사고 | 운영자·광고계정·캠페인별 예산 exact match와 종료 후 pause를 적용한다. |
| 외부 API 장애 | DB 선접수, lease·재시도와 idempotent 외부 효과 기록으로 입력과 진행 상태를 보존한다. |
| 개인정보 책임 증가 | 이름·이메일·동의를 최소 수집하고 이메일 중복 방지·목록 마스킹·소유자 RLS를 적용한다. |

## 3일 실행 목표

- G0: `CampaignSpec`과 fixture 검증
- G1: 같은 fixture로 실제 공개 랜딩과 캐러셀 파일 생성
- G2: 외부 API 없는 공개·응답·판단·PNG/ZIP 전체 흐름
- G3: Supabase 실제 공개와 시크릿 창 응답
- G4: Anthropic adapter와 명시적 실패·fixture 발표 fallback
- 발표 전: 기능 동결, 전체 검증, 네트워크 차단 리허설과 백업 영상

## 다음 검증

- 예비창업자의 최근 검증 시도와 포기 지점 인터뷰
- 현재 도구 조합에서 실제 수작업 단계 측정
- mock 캠페인을 직접 조작했을 때 이해되지 않는 상태 관찰
- 개인 건당 결제와 기관 기수 계약의 지불 의향 분리 검증

측정 전에는 사용자 수, 전환율, 절감 시간, 매출과 시장 점유율을 기입하지 않는다.
