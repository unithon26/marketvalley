# 발표 데모 실행서

상태: mock 종단 흐름 검증 완료
목표 시간: 3분

이 절차는 외부 API와 계정 없이 발표용 fixture를 사용하는 수동 리허설 기준이다. 화면의 응답과 결과는 실제 사용자 조사가 아닌 목데이터다.

## 발표 전 준비

```bash
pnpm install --frozen-lockfile
pnpm check
pnpm build
pnpm test:e2e
pnpm dev
```

1. `http://localhost:3000`이 열리는지 확인한다.
2. 브라우저 폭 375px과 발표 노트북 화면에서 한 번씩 확인한다.
3. `/campaigns/demo`의 `데모 데이터 초기화`로 기존 브라우저 응답을 지운다.
4. 다운로드 폴더에서 이전 PNG·ZIP을 정리한다.
5. 네트워크를 끈 상태에서도 핵심 흐름이 끝나는지 확인한다.

발표자가 모든 화면을 직접 클릭한다. E2E 도구는 개발 검증에만 사용하며 발표 자동 재생 기능을 만들지 않는다.

## 3분 수동 흐름

1. 20초 — 첫 시장 반응을 보기 전에 랜딩, 카드, 문구와 취합을 각각 해야 했던 기존 흐름을 설명한다.
2. 25초 — 홈에서 `새 캠페인`을 누르고 `/new`의 `예시 불러오기`로 아이디어 입력을 채운다.
3. 30초 — 가설 승인 단계에서 고객·문제·기대 신호·반증 조건과 사람이 승인할 기준을 확인한다.
4. 35초 — 승인 한 번으로 진행 화면을 거쳐 공개 경로, 캐러셀 ZIP과 게시 문구가 준비되는 것을 보여준다.
5. 25초 — 결과 화면의 공개 URL로 `/p/demo`를 새 탭에서 연다.
6. 25초 — 공개 페이지 CTA에서 개인정보 없는 선택형 응답을 하나 제출한다.
7. 30초 — 캠페인 결과 화면에서 응답 분포가 바뀐 것을 확인하고 발표자가 `계속 검증`, `메시지 수정`, `보류` 중 하나를 선택한다.
8. 20초 — PNG 5장이 든 ZIP을 내려받고 `Meta 게시 준비`의 문구·CTA·URL이 같은 spec에서 왔음을 보여준다.
9. 10초 — 콘텐츠를 더 만든 것이 아니라 고객을 만나기 전 반복 제작·취합 업무를 없앴다고 정리한다.

## 실패 대응

- 화면이 꼬이면 결과 화면의 `데모 데이터 초기화` 후 홈에서 새 캠페인을 다시 시작한다.
- 외부 네트워크는 mock 흐름에 필요하지 않다.
- 공개 페이지의 응답이 결과 화면에 바로 보이지 않으면 결과 화면을 새로고침한다.
- PNG/ZIP 다운로드가 브라우저 정책으로 막히면 사전에 받아 둔 결과 파일로 전환한다.

## 발표에서 하지 않는 주장

- 시장성이 검증됐다.
- 전환율이나 매출이 개선됐다.
- 실제 Meta 광고가 등록 또는 집행됐다.
- mock 응답이 실제 사용자 조사 결과다.
