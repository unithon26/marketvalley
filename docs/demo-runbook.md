# 발표 데모 실행서

상태: mock 종단 흐름 검증 완료
목표 시간: 3분

이 절차는 외부 API와 계정 없이 발표용 fixture를 사용하는 수동 리허설 기준이다. 화면의 응답과 결과는 실제 사용자 조사가 아닌 목데이터다.

## 발표 전 준비

```bash
pnpm install --frozen-lockfile
pnpm check
pnpm build
pnpm test:e2e
pnpm dev
```

1. `http://localhost:3000`이 열리는지 확인한다.
2. 브라우저 폭 375px과 발표 노트북 화면에서 한 번씩 확인한다.
3. `/campaigns/demo`의 `데모 데이터 초기화`로 서버 메모리의 추가 응답과 판단을 지운다.
4. 다운로드 폴더에서 이전 PNG·ZIP을 정리한다.
5. 네트워크를 끈 상태에서도 핵심 흐름이 끝나는지 확인한다.

발표자가 모든 화면을 직접 클릭한다. E2E 도구는 개발 검증에만 사용하며 발표 자동 재생 기능을 만들지 않는다.

## 3분 수동 흐름

1. 20초 — 첫 시장 반응을 보기 전에 랜딩, 카드, 문구와 취합을 각각 해야 했던 기존 흐름을 설명한다.
2. 25초 — 홈에서 `새 캠페인`을 누르고 `/new`의 `예시 불러오기`로 배경 입력을 채운다.
3. 20초 — `다음`을 눌러 솔루션을 확인하고 `캠페인 만들기`를 누른다.
4. 25초 — 진행 화면을 거쳐 공개 경로, 캐러셀 ZIP과 게시 문구가 준비되는 것을 보여준다.
5. 20초 — 결과 화면에 발급된 `/p/[slug]` 공개 URL을 새 탭에서 연다.
6. 20초 — 공개 페이지 CTA에서 개인정보 없는 선택형 응답을 하나 제출한다.
7. 25초 — 캠페인 결과 화면이 4건에서 5건으로 갱신되고 기준에 도달한 것을 확인한 뒤 발표자가 다음 행동을 선택한다.
8. 15초 — PNG 5장이 든 `[campaignId]-carousel.zip`과 `Meta 게시 준비`가 같은 spec에서 왔음을 보여준다.
9. 10초 — 콘텐츠를 더 만든 것이 아니라 고객을 만나기 전 반복 제작·취합 업무를 없앴다고 정리한다.

## 실패 대응

- 화면이 꼬이면 결과 화면의 `데모 데이터 초기화` 후 홈에서 새 캠페인을 다시 시작한다.
- 외부 네트워크는 mock 흐름에 필요하지 않다.
- 공개 페이지의 응답은 최대 2초 안에 결과 화면에 반영된다. 지연되면 결과 화면을 새로고침한다.
- 응답·판단·초기화 오류 문구가 보이면 성공으로 간주하지 말고 같은 버튼으로 재시도한다.
- PNG/ZIP 다운로드가 브라우저 정책으로 막히면 사전에 받아 둔 결과 파일로 전환한다.

## 발표에서 하지 않는 주장

- 시장성이 검증됐다.
- 전환율이나 매출이 개선됐다.
- 실제 Meta 광고가 등록 또는 집행됐다.
- mock 응답이 실제 사용자 조사 결과다.
