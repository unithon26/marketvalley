# 3분 발표 실행서

상태: 운영 종단 흐름과 별도 수집 완료 예시 준비
기준일: 2026-08-26

## 발표 전 확인

1. [공식 서비스](https://marketvaley.vercel.app/api/health)가 `status: ok`이고 generator, repository, quota, reservations가 모두 ready인지 확인한다.
2. 발표용 Google 계정으로 로그인해 실제 진행 중이거나 완료된 광고 한 건이 보이는지 확인한다.
3. 공개 랜딩, 카드뉴스 5장과 리포트가 같은 상품명·특징·CTA를 쓰는지 확인한다.
4. 광고 수집이 끝났다면 실제 `/campaigns/[id]` 최종 리포트를 사용한다.
5. 24시간 수집이 진행 중이면 실제 `/campaigns/[id]/progress`를 먼저 보여준 뒤 `/campaigns/[id]/presentation`으로 이동한다. 이 경로는 수집 대기만 건너뛴 예시이며 화면 상단에 명확히 표시된다.
6. Chrome 확대 100%, 알림·개인 탭 숨김, 다운로드 폴더 정리와 안정적인 네트워크를 확인한다.

실제 광고를 새로 만드는 시연은 기존 live run이 없고 고정 예산을 다시 확인한 경우에만 한다. 발표 중 예산을 늘리거나 종료 광고를 다시 활성화하지 않는다.

## 발표 흐름

1. 25초 — 예비창업가가 첫 반응 전에 고객·문제·가치를 다시 쓰고, 랜딩과 카드 5장을 조판하고, Ads Manager에 옮기고, 다음 날 데이터를 다시 합치는 기존 흐름을 설명한다.
2. 25초 — Google 로그인 뒤 계정 소유 프로젝트만 나타나는 홈을 보여준다. seed 프로젝트와 예시 입력 버튼이 없다는 점을 짧게 확인한다.
3. 30초 — `/new`의 두 입력을 보여주고 `광고 만들기` 뒤 접수 상태가 먼저 저장되는 과정을 설명한다. 브라우저를 닫아도 서버 worker가 계속한다.
4. 25초 — 진행 화면의 `접수 → 준비 중 → 수집 중 → 결과 도착`과 현재 실제 상태를 보여준다. 준비 중 입력 화면으로 돌아가지 않고 실패·재시도 상태도 DB에 남는다고 설명한다.
5. 30초 — 실제 공개 랜딩과 서버 렌더 카드뉴스를 연다. 같은 결과가 화면 미리보기, ZIP과 Meta 광고 소재에 사용된다는 점을 보여준다.
6. 25초 — 수집 완료 리포트에서 Meta 노출·클릭, 고유 방문, 동의 기반 예약자명단과 마스킹 이메일을 보여준다. 발표용 예시라면 상단 라벨을 함께 보여준다.
7. 10초 — `실제 광고 활성화`, `PAUSED 초안 만들기` 같은 수동 운영 버튼이 없고, 마지막 선택은 사람이 하는 다음 행동임을 보여준다.
8. 10초 — “AI가 콘텐츠를 더 만든 것이 아니라, 첫 고객을 만나기 전 반복 제작·등록·확인·취합을 없앴다”로 마무리한다.

## 실패 대응

- Vercel 응답이 불안정하면 Oracle의 동일 source SHA 배포 URL로 전환한다.
- 로그인 세션이 만료되면 Google 로그인 뒤 원래 진행 화면으로 복귀한다.
- 실제 광고 수집이 아직 끝나지 않았으면 완료라고 말하지 않는다. 진행 화면과 명시적 발표용 예시를 분리해 보여준다.
- 카드 다운로드가 브라우저 정책으로 막히면 화면의 서버 PNG 5장과 API Content-Type·크기를 보여준다.
- 외부 API 장애는 fixture 성공으로 설명하지 않는다. 저장된 `RETRY_WAIT` 또는 `FAILED` 상태와 재개 경계를 설명한다.

## 하지 않는 주장

- 예약이나 클릭만으로 시장성이 검증됐다.
- 매출·전환율·광고 효율이 개선됐다.
- 발표용 예시 수치와 예약자가 실제 사용자 조사 결과다.
- marketvalley가 통계적 시장조사나 사람의 사업 판단을 대신한다.
