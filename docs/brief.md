# 제품 브리프

상태: 발표용 fixture 종단 구현 기준 v0.6
기준일: 2026-08-25
제품명: marketvalley

확정 제품명은 `marketvalley`이며 공개 문구, 코드 식별자와 저장소에서 같은 소문자 표기를 사용한다.

## 한 문장

marketvalley는 아이디어는 있지만 제품을 아직 만들지 않은 예비창업가와 초기 1인 사업자가 첫 시장 반응을 확인하기 전에 반복하던 검증 캠페인 제작과 결과 취합을 없애고, 하나의 검증 가설에서 공개 랜딩페이지, 인스타그램 캐러셀, 광고 문구와 실제 관심 신호를 한 번에 연결한다.

## 문제

초기 아이디어를 검증하려는 예비창업가와 초기 1인 사업자는 아직 제품도 팀도 없는 상태에서 다음 일을 직접 오가며 수행한다.

1. 누구의 어떤 문제를 검증할지 다시 정리한다.
2. 가치 제안과 후킹 문구를 여러 버전으로 작성한다.
3. 랜딩페이지 구조와 문구를 만든다.
4. 웹 빌더에서 페이지를 조립하고 공개한다.
5. 인스타그램 카드의 흐름과 각 장의 문구를 만든다.
6. 디자인 도구에서 장마다 조판하고 포맷을 맞춘다.
7. 캡션, CTA, 링크를 채널마다 다시 복사한다.
8. 유입과 관심 반응을 별도로 모아 다음 판단을 준비한다.

이 과정의 핵심 비용은 단순 작성 시간이 아니다. 같은 가설을 여러 도구에 반복해서 옮기면서 메시지가 달라지고, 준비 작업에 지쳐 실제 고객 반응을 확인하기 전에 검증이 멈춘다는 점이다.

이 문제 설명은 현재 팀의 가설이다. 실제 사용자 인터뷰나 관찰 전에는 시장 전체의 검증된 사실처럼 표현하지 않는다.

## 대상 사용자

첫 번째 사용자는 아이디어는 있지만 제품을 아직 만들지 않은 예비창업가 또는 초기 1인 사업자로, 다음 조건을 모두 만족하는 사람이다.

- 혼자 또는 극소수로 사업을 준비한다.
- 아이디어는 있지만 완성된 제품과 브랜드 자산은 없다.
- 개발자, 마케터, 디자이너를 별도로 고용하기 전에 수요 신호를 확인하려 한다.
- 첫 검증 채널로 공개 랜딩페이지와 인스타그램을 사용할 수 있다.

대행사, 이미 마케팅 조직과 브랜드 시스템이 있는 회사, 실제 광고 자동 집행이 필요한 전문 마케터는 초기 대상이 아니다.

## 사용자가 맡는 판단과 사라지는 일

사람에게 남기는 것:

- 해결하고 싶은 문제와 대상 고객을 선택한다.
- 입력하는 배경·솔루션의 사실성을 책임진다.
- 반응과 사전 기준을 보고 계속 검증하거나 메시지를 바꾸거나 보류할지 결정한다.
- 실제 고객과 대화한다.

제품이 없애는 것:

- 가설을 채널별 기획 문서로 반복해서 다시 쓰는 일
- 랜딩페이지와 카드뉴스 문구를 따로 작성하는 일
- 카드마다 직접 조판하고 크기를 맞춰 파일로 정리하는 일
- 서로 다른 결과물의 메시지 불일치를 찾아 고치는 일
- 공개 페이지의 관심 반응을 별도 문서에 다시 취합하는 일

## 제품 약속

사용자는 제품 배경과 솔루션을 입력한다. 시스템은 동일한 구조화 데이터로 다음 결과를 만들고 게시하며, 사용자는 실제 반응 뒤의 판단을 맡는다.

- 검증 가설 1개와 반증 조건
- 공개 가능한 모바일 랜딩페이지 1개
- 같은 메시지를 사용하는 인스타그램 캐러셀 5장
- 후킹 문구 3개, 캡션 1개, CTA 1개
- 카드 PNG 5장과 ZIP
- 같은 문구·PNG 5장·절대 공개 URL을 묶은 `Meta 게시 준비` ZIP
- 랜딩페이지 방문자의 개인정보 없는 선택형 관심 응답
- 사전에 정한 판단 기준과 사람의 다음 행동 선택 화면

이 제품은 시장성을 보장하거나 시장조사를 대신한다고 주장하지 않는다. 첫 검증 실험을 시작하기 위한 제작·정리 업무를 없애고, 실제 반응을 한곳에 연결한다.

## 핵심 사용자 흐름

1. 사용자가 제품을 만들게 된 배경을 입력한다.
2. 사용자가 제공할 솔루션을 입력하고 캠페인 생성을 시작한다.
3. 시스템이 `검증할 고객·문제·해결·기대 신호·반증 조건`을 하나의 `CampaignSpec`으로 구성하고 캠페인을 게시한다.
4. 사용자는 결과 화면에서 공개 경로, 캐러셀 ZIP, Meta 게시 준비 ZIP과 복사 가능한 문구를 받는다.
5. 공개 페이지 방문자가 CTA 뒤의 짧은 선택형 질문에 답하면 익명 응답이 기록된다.
6. 사용자는 응답과 사전 판단 기준을 함께 보고 `계속 검증`, `메시지 수정`, `보류` 중 다음 행동을 직접 선택한다.

현재 발표용 구현은 외부 AI 없이 입력 키워드에 따라 검증된 reference fixture 3종 중 하나를 선택한다. OpenAI adapter를 연결하기 전까지 새로운 시장 사실이나 맞춤 결과를 생성한다고 주장하지 않는다.

## 성공 기준

해커톤 MVP 성공은 다음 조건으로 판단한다.

- 하나의 실제 입력이 유효한 구조화 가설과 모든 P0 결과물로 이어진다.
- 랜딩과 캐러셀의 대상 고객, 문제, 가치 제안, CTA가 서로 모순되지 않는다.
- 사용자가 디자인 도구나 웹 빌더를 열지 않고 공개 URL과 5장의 게시용 PNG를 얻는다.
- 광고 등록 직전에 필요한 미디어, 문구, CTA, 대상 고객 가설과 공개 URL이 한 화면에 모인다.
- 공개 URL에서 제출한 선택형 응답 1건이 캠페인 화면에 실제로 반영된다.
- 응답 수가 기준보다 부족하다는 사실과 사람이 선택할 다음 행동이 한 화면에 보인다.
- 라이브 AI나 이미지 생성이 실패해도 준비된 동일 흐름의 데모가 끝까지 동작한다.
- 발표에서는 구현 완료 후 실제 조작을 세어 `before/after` 수동 단계 수를 보여준다. 미측정 시간 절감률은 주장하지 않는다.

## 차별화

HubSpot Campaign Assistant는 랜딩페이지·이메일·광고 카피 생성을, Canva는 소셜 디자인·리사이즈·게시를, Lovable은 자연어 기반 랜딩 제작과 배포를 이미 제공한다. 따라서 “여러 마케팅 결과물을 AI로 만든다”는 것은 차별점이 아니다.

marketvalley의 차별점은 아직 서비스나 URL도 없는 아이디어에서 시작해 다음을 하나의 닫힌 흐름으로 강제하는 것이다.

- 검증 가능한 가설과 반증 조건을 먼저 고정한다.
- 모든 결과물이 같은 `CampaignSpec`을 사용한다.
- 결과물이 예쁜지에서 끝나지 않고 실제 관심 신호를 원래 가설에 연결한다.
- 최종 화면이 더 만들라고 권하지 않고 `계속 검증`, `메시지 수정`, `보류`라는 사람의 판단으로 돌아온다.

## 범위 제외

- P0의 Instagram 또는 Meta 실제 계정 연결과 광고 객체 쓰기
- 광고 결제수단 등록, 자동 활성화, 무인 예산 증액·재시작과 성과 최적화
- 시장성, 매출, 성공 가능성의 자동 판정 또는 보장
- 범용 웹사이트·앱 코드 생성
- 여러 랜딩 템플릿과 자유 배치 편집기
- 산출물을 화면에 재현하는 사전 확인·편집 화면
- 로그인, 팀 협업, 결제, 구독
- AI가 글자가 포함된 카드 전체를 이미지로 생성하는 방식
- 대규모 크롤링과 경쟁사 시장조사
- 통계적으로 유의한 A/B 테스트 판정

해커톤 P1은 P0와 발표 준비가 모두 안정된 뒤 팀 소유 테스트 계정에서 `PAUSED` 객체 생성까지만 허용한다. 실제 제품의 OAuth, 사람 승인과 Insights 경계는 `docs/decisions/0003-stage-meta-automation-behind-human-approval.md`를 따른다.

실제 인터뷰나 사용 근거가 없는 베타테스터 후기, 고객 인용문, 사용 인원, 수상·인증·효능 수치는 생성하거나 발표 자료에 넣지 않는다.

## 지금 검증할 가설

- 예비창업가와 초기 1인 사업자는 아이디어가 없어서가 아니라 검증 캠페인 제작을 시작하기 어려워 검증을 미룬다.
- 랜딩, 인스타그램, 문구가 한 가설에서 동시에 만들어지면 채널별 반복 제작이 실제로 줄어든다.
- 사용자는 완전 자동 게시보다 공개 전 사실 확인과 최종 승인 권한을 원한다.
- 개인정보 없는 문제 공감 또는 사용 의향 응답은 생성 도구와 검증 루프의 차이를 보여줄 최소 신호가 될 수 있다.

가능하면 구현 초기에 대상 조건을 만족하는 예비창업가 또는 초기 1인 사업자 3명에게 현재 흐름과 산출물을 보여준다. 질문은 기능 선호가 아니라 최근 아이디어를 검증하려다 실제로 수행했거나 포기한 행동에 집중한다.
